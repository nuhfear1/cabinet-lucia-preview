# Procédure — Incidents et continuité

## Incidents concernés

- site public indisponible ;
- portail inaccessible ;
- échec de connexion généralisé ;
- demande de rendez-vous non transmise ;
- erreur d’affichage ou mauvaise information publiée ;
- suspicion d’accès non autorisé ;
- perte, modification ou exposition possible de données ;
- assistant donnant une réponse inadaptée ;
- agenda ou base indisponible.

## Réflexe initial

1. Ne pas improviser de correction directement en production.
2. Noter l’heure, l’écran concerné et l’action qui a précédé l’incident.
3. Limiter l’impact : suspendre une fonction publique si elle produit des informations erronées.
4. Informer la personne responsable selon la chaîne d’escalade validée.
5. Conserver les éléments utiles sans partager de données sensibles inutilement.

## Niveaux proposés

- **Niveau 1 — gêne mineure** : défaut visuel, texte incorrect sans impact sur une donnée ou une décision.
- **Niveau 2 — fonction dégradée** : demande ou action impossible, sans exposition apparente de données.
- **Niveau 3 — incident critique** : suspicion d’accès non autorisé, données exposées, mauvaise association de dossier ou information médicale dangereuse.

Les délais de réaction et les responsables nominatifs restent `À VALIDER`.

## Continuité manuelle

Lorsque le système est indisponible :

- utiliser uniquement le canal de secours autorisé par Lucia ;
- recueillir le minimum nécessaire ;
- ne pas utiliser de fichier personnel ou d’outil non approuvé ;
- numéroter les demandes reçues pendant l’interruption ;
- les ressaisir après rétablissement avec une mention de l’origine ;
- vérifier qu’aucun doublon n’a été créé.

## Après rétablissement

1. Vérifier le retour du service.
2. Tester un parcours fictif autorisé.
3. Contrôler les demandes reçues avant et après l’incident.
4. Traiter les doublons ou demandes manquantes.
5. Documenter la cause connue, la correction et les mesures préventives.
6. Informer les personnes concernées lorsque cela est nécessaire et autorisé.
